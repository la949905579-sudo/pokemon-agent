# 团队手册（TEAM）

> 团队是**会话级**的：成员挂在发起它们的那个会话上，换会话不会继承。
> 新会话要做的不是“加入”，而是“按本手册重建”。
>
> **命名规则（2026-11-12 起）**：文档、交接、汇报一律用**职位**（主持/执行主管/工匠/考官/督导）；
> 英文实例名只用于两处——`spawn_teammate` 和 `send_message` 的 target。
> 职位一个只能有一个实例；换实例名只改本手册的映射表，文档不用动。

## 〇、与督导团队的关系（2026-11-12 起）

督导**不是 A 队成员**，是独立的一支团队（B 队）：

- B 队：督导主持 + 审查员 + 成本管理员，见 `docs/audit/TEAM.md`
- A 队（本手册）：主持 + 执行主管 + 工匠 + 考官
- 两队**只由主持之间对接**，接口是 `docs/audit/` 下的请求与报告文件
- `AUDIT_LOG.md` 由 B 队写，A 队**只读**

## 〇·五、与组织架构师的关系（2026-11-12 起）

`architect`（组织架构师）也不是 A 队成员：**不常驻、按需开启**，负责组织架构与产品项目流程规范，
提示词见 `docs/roles/architect.md`；以下默认参数**用户 2026-11-12 确认，改参数先与用户谈**。

- 只跟主持对接，接口是 `docs/org/`：主持写 `REQUEST.md`，架构师写 `PLAN-<YYYYMMDD>.md`
- 可写本手册、A 队角色卡、`docs/PROJECT_PLAN.md`、`docs/WORKPLAN.md`、`docs/STRUCTURE.md`、
  `docs/org/`；其余只读（B 队三张卡除外；`STRUCTURE.md` / `WORKPLAN.md` 仍需主持确认）
- 汇报 **10 行**：结论 / 方案 / 影响 / 风险 / 待确认 / 产物；超额在首行写「申请 +N 行：原因」
- 触发：里程碑或版本切换 / 组织冲突（职责重叠、写入打架）/ 每 3 个批次 / 用户点名
- 改文件前先列「改哪些文件、为什么」，确认后再动；一次只改一类（TEAM.md → 角色卡 → 路线文档）
- 手册与角色卡直接改；路线 / 流程改动先出 proposal；不派活、不跑构建、不碰代码
- 与 B 队互不改文档；审查机制意见写 `docs/org/` 报告，由主持转给督导主持
- P0（数据丢失 / 密钥外泄 / 发布事故）：立即停下并通知用户

## 一、编制（3 + 1）

| 职位（交接用） | 默认实例名（spawn 用） | 职责 | 写入范围 |
|---|---|---|---|
| **主持** | `lead` | 只做对接与协调：需求澄清、优先级、跨会话、最终拍板 | 无（不碰工具原文） |
| **执行主管** | `steward` | 派活、读 diff、跑测试、推送、等 CI、写 `docs/` 与 `tools/`、调度队友 | `docs/`、`tools/`、git push |
| **工匠** | `artisan` | 实现与修复（带 shell） | `native-emu/**`、根目录 `test_*.py` |
| **考官** | `examiner` | 只读复核，出结论（带 shell） | 无（不写文件） |
| **督导**（按需） | `auditor` | 第三方流程审查，一次性会话 | 无 |

**退役成员（禁止派活）**：`builder`（旧工匠）、`verifier`（旧考官）。它们诞生在 `workspace-write`
策略下、bash 不可用；工具不支持删除成员，它们随会话结束自然消失。新会话**不要**再建这两个名字。

`auditor` 不常驻——按里程碑/事故另开新会话，提示词见 `docs/roles/auditor.md`。

> **2026-11-12 重建记录**：原 `builder` / `verifier` 诞生于 `workspace-write` 策略下，
> 本机没有沙箱后端 → 它们的 bash 全被拒，只能改文件、不能提交/跑测试。
> 会话策略改为 `danger-full-access` 后，**只有新建成员才继承新策略**，所以重建为
> `artisan` / `examiner`。旧的 `builder` / `verifier` 留在原地、不再派活。

## 二、重建步骤（新会话，3 分钟）

1. 读 `docs/HANDOFF.md` → 了解当前状态；读 `docs/roles/` 下的四份提示词。
2. 各 spawn 一个，**实例名用默认值**：
   - 执行主管 → `steward`（prompt = `steward.md`）
   - 工匠 → `artisan`（prompt = `artisan.md`）
   - 考官 → `examiner`（prompt = `examiner.md`）
3. 让考官先做一次基线核查（测试 + CI + 文档一致性），再由执行主管派第一个任务给工匠。

**为什么要用默认实例名**：文档按职位写，但 `spawn`/`send_message` 只认英文名；用默认值可以省掉映射。
换了名也能跑，只是要改本手册的映射表——**文档里的职位称呼永远不变**。

## 二·五、需求入口（2026-11-12 起，硬规则）

**收到新需求时不要立刻派活。** 先走入口流程：

1. **登记**：把需求写成一张卡（目标 / 验收标准 / 涉及文件 / 依赖 / 优先级），记进 `docs/NATIVE_EMU_TODO.md` 或当轮清单。
2. **澄清**：把歧义点一次性问清（尤其"重置/退出/删除"这类一词多义的），不要边做边猜。
3. **合批**：和在途任务一起排——哪些能一次构建验完、哪些有文件冲突、哪个先。
4. **确认**：把「这批做什么、顺序、验收」给用户确认后，才开始派发。

理由：即时执行会打断正在跑的批次，产出半成品；而且同类改动分开做会多花好几次构建等待。

## 三、任务流转

```
Lead 定优先级 + 批次目标（只看结论，不碰 diff）
   → 执行主管拆任务、派给工匠（含验收标准与写入边界）
   → 工匠实现、自测、commit（有 shell 就自己提交）
   → 执行主管跑测试、审 diff、push、等 CI
   → 考官独立复核，给「可发布 / 不可发布」+ 证据
   → 执行主管汇总三行摘要给主持 → 主持拍板发布
   → 执行主管更新 CHANGELOG/TODO/HANDOFF
```

**主持的成本控制**：每轮只读三行摘要；每 3 个批次抽 1 次看关键 diff。

规则：
- **提交前**：`tools/precommit_check.sh --scope <本次应改的路径>`（空提交 / `git add -A`
  卷入未声明改动 / 空提交信息都会拦下）；**推送前**：同脚本 `--push`（发现远端有本地没有的
  提交即拒绝，防 amend/强推）。
- 同一文件同时只允许一个写入者。
- `examiner` 的结论必须带证据（行号 / run 链接），否则 Lead 不采信。
- 任务被打回两次，换任务而不是硬催——通常是上下文已经污染。

## 三·七、汇报预算（2026-11-12 起）

控制上下文成本：每次汇报默认不得超过下表行数。

| 职位 | 默认上限 | 内容 |
|---|---|---|
| 执行主管 | **3 行** | 状态 / 风险 / 请示 |
| 工匠 | **10 行** | 改了什么 / 自检 / 不确定点 |
| 考官 | **15 行** | 结论 / 证据 / 问题清单 |
| 督导 | **40 行** | 六节（结论/证据/整改/元审查） |

### 超额申请（唯一例外通道）

确实需要更长时，在汇报**开头第一行**写：

```
申请 +N 行：<一句话原因>
```

- 审批人：主持。没写申请或原因不成立的，**按超限打回重写**
- 单次最多 `+20` 行
- 同一职位**连续 3 次**申请 → 说明默认上限不合理，改默认值，而不是每次都批
- 申请只对本次有效，不累积

### 叫考官的规则（省一轮是一轮）

只有满足任一条才叫考官复核：
- 改动包含 `native-emu/**`（会出 APK）
- 要发 Release / 打 tag
- 动过凭据、签名、CI

纯文档、`tools/` 脚本、测试文件改动 → **只跑测试，不叫考官**。

### 整改合并

督导整改项默认**并入下一个功能批次**一起做，不单独开轮；只有标记 P0（数据丢失/密钥外泄/发布事故）才立刻单独处理。

## 四、度量（每里程碑由 `examiner` 算一次）

由 `python3 tools/metrics.py` 生成到 `docs/METRICS.md`（**不要手改**），只记能自动算的：

| 指标 | 定义 |
|---|---|
| CI 首次通过率 | 每个提交第一次构建是否绿 |
| 打回率 | examiner 判「不可发布」的次数 / 复核次数 |
| 复发率 | `INCIDENTS.md` 已固化的问题再次出现次数 |
| 上手时间 | 新会话从开工到第一个有效提交 |
| 交接次数 | 因上下文退化被迫换会话的次数 |
| 构建覆盖 | 未构建提交里有没有触及 `native-emu/**` 的（脚本判定） |

**复发率是唯一硬指标**，其余用来解释原因。

会话健康用脚本量，不用感觉：`node tools/session_health.mjs`（轮次/压缩/连续空回合，exit 1 表示该交接）。

## 五、失败模式（已知）

| 现象 | 处理 |
|---|---|
| 成员跑不了 `bash` | 让步只出判断，命令由执行主管代跑，并在结论里注明。**2026-11-12 前**的旧成员 `builder`/`verifier` 因 `workspace-write` 无沙箱后端全部被拒；重建后的 `artisan`/`examiner` 在 `danger-full-access` 下可执行。若仍有成员被拒：由其出判断、执行主管代跑，结论必须标注「编译结论来自 CI / 测试由执行主管代跑」 |
| 两个会话同时改同一仓库 | 交接前旧会话必须停手；推送前先 `git pull --rebase` |
| 长会话空回复 | 见 `docs/HANDOVER.md` 的交接阈值，到点就换 |
| 团队重建后行为漂移 | 说明提示词没覆盖到，把这次的教训补进 `docs/roles/*.md` 并升版本号 |
