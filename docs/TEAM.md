# A 队团队手册（TEAM）

> B 队（独立督导团队）手册见 `docs/audit/TEAM.md`。
> **2026-11-13 重建版**：依据用户逐项核对结果与 `docs/org/PLAN-20261113-4.md`（重建总方案）。
> 团队是**会话级**的：成员挂在发起它们的会话上，换会话不继承；新会话按本手册 §二 重建。

## 〇、三条铁律

1. **单会话单身份**：一个会话只戴一顶帽子；宿主身份 ≠ 职位。做了不属于本职位的事（派活 / 提交推送 / 指挥成员）即算越位 → 交接换新会话，不在原地继续。
2. **中文职位名沟通**：文档、交接、汇报一律用中文职位名；英文实例名只出现在 `spawn_teammate` / `send_message`。
3. **一个职位一个活跃实例**；换实例名只改本手册映射表，文档不动。

## 一、编制

### 1.1 会话（各自独立；只有该会话主持能 spawn 成员）

| 职位 | 实例名 | 常驻 | 职责 | 写入范围 |
|---|---|---|---|---|
| **统筹主持** | `lead` | 是，唯一 | 对接用户、定优先级、派活、拍板、跨会话协调；不读 diff / 构建日志 / 长文档 | 无（保留直接修改权，改后留痕 `HANDOFF`） |
| **独立督导**（B 队） | `audit-lead` | 否，按需 | 审查、成本巡检、轮次巡检、整改清单 | `docs/audit/AUDIT.md`、`docs/audit/AUDIT_LOG.md`、`docs/audit/**`、`docs/roles/b/**` |
| **组织规划** | `architect` | 否，每任务新开 | 组织架构、流程、文件规范设计 | `docs/TEAM.md`、`docs/roles/a/**`、`docs/roles/org/**`、`docs/PROJECT_PLAN.md`、`docs/WORKPLAN.md`、`docs/STRUCTURE.md`、`docs/org/**` |
| **策略顾问** | `advisor` | 否，用户需要时开 | 参谋：理需求、挑毛病、核对回执是否可信；不代拍板 | 无（只读） |

### 1.2 成员（子代理；只有会话主持能 spawn，子代理不能再 spawn）

| 职位 | 实例名 | 由谁 spawn | 可写 | 汇报上限 |
|---|---|---|---|---|
| **助理** | `assistant` | 统筹主持 | 状态类文档（`HANDOFF`/`HANDOVER`/`CHANGELOG`/`NATIVE_EMU_TODO`）、`tools/`、`METRICS`（只经脚本） | 3 行 |
| **工匠** | `artisan` | 统筹主持 | `native-emu/**`、`tests/**` | 10 行 |
| **考官** | `examiner` | 统筹主持 | 无（只读复核） | 15 行 |
| **审查员** | `auditor` | 独立督导 | 无（报告文字交督导落盘） | 15 行 |
| **成本管理员** | `audit-cost` | 独立督导 | 无 | 10 行 |
| **分工规划员** | `role-planner` | 组织规划 | `docs/org/` 草稿 | 10 行 |
| **结构规划员** | `struct-planner` | 组织规划 | `docs/org/` 草稿 | 10 行 |

- **助理**：每批新开（目的是延长统筹主持寿命，不许跨批累积）。
- **工匠**：本期 1 名；下一期经「当期组织规划 + 用户」共同分析后最多再 +1（总数 ≤2）。
- **考官**：**任何批次都要叫**；纯文档批次走轻量复核（≤5 行，只看引用 / 一致性 / 索引）。
- **组织规划**：两个子代理只在提纲经用户确认后开，用完即关，同一时间最多 2 个。
- 退役名：`builder`、`verifier`、`steward` 永久禁用（历史文档不回改）。

## 二、重建步骤（新会话，可直接复制）

> 你是统筹主持。先读 `docs/HANDOFF.md`、`docs/TEAM.md`、`docs/HANDOVER.md`；跑 `python3 run_tests.py` 与 `node tools/session_health.mjs` 做基线；spawn 助理（`assistant`）与工匠（`artisan`），每批复核时再加考官（`examiner`）。第一批任务从 `docs/NATIVE_EMU_TODO.md` 与 HANDOFF 取。

开工自检三连（任一不满足先补，不开工）：
1. `git status --short` 为空
2. `git rev-list --count origin/master..HEAD` = 0
3. `python3 tools/gen_files_index.py --check` = 0

## 三、主流程（12 步）

1. 需求登记（统筹主持，小卡：目标/验收/文件/依赖/优先级）
2. 澄清（≤1 轮，歧义一次问清）
3. 合批（同文件同批；跨模块拆批；文档改动并入功能批）
4. 用户确认（做什么 / 顺序 / 验收）
5. 派活（统筹主持 spawn 助理 + 工匠；助理拆任务、写验收与写入边界）
6. 实现（工匠，只改批准范围 + 自测）
7. 机械门禁 → 提交（助理；只报事实，不判质量）
8. 独立复核（考官；每批；「可发布 / 不可发布」+ 证据）
9. 推送前检查（助理）
10. 发布（助理执行，统筹主持拍板；tag + CHANGELOG 同批更新）
11. 状态同步（助理：HANDOFF / CHANGELOG / TODO / METRICS 与索引重生成）
12. 回执（统筹主持；≤10 行）

- 一批 = 一次可构建、可验收的最小功能集合；目标周期 **≤1 天**，超了拆。
- **每批一条记录**写 `docs/BATCHES.md`（只追加、不改历史条目）；`HANDOFF` 只保留最近 2–3 批摘要。

## 三·五、门禁（任一红 → 整批停，不推半成品）

| 门禁 | 检查项 |
|---|---|
| 提交前 | `tools/precommit_check.sh --scope`、`run_tests.py`、无空提交、无范围外文件 |
| 推送前 | `tools/precommit_check.sh --push`、CI 绿、考官「可发布」、涉及 `native-emu/**` 有真机记录 |
| 发布前 | `CHANGELOG` / `HANDOFF` 已更新、索引 `--check`=0、tag（按需） |

- 回滚：未推送 `git reset --hard`；已推送 `git revert`（**禁止 force push**）；已发版撤 tag 并重建上一版，记 `INCIDENTS`。
- 热修：只修 P0，当天修，仍过门禁 + 考官轻量复核；极端情况允许「先发后补审」，但必须在 `docs/history/INCIDENTS.md` 留痕。

## 三·七、汇报预算

| 职位 | 默认上限 | 内容 |
|---|---|---|
| 助理 | **3 行** | 状态 / 风险 / 请示 |
| 工匠 | **10 行** | 改了什么 / 自检 / 不确定点 |
| 考官 | **15 行** | 结论 / 证据 / 问题清单 |
| 组织规划 | **10 行** | 结论 / 方案 / 影响 / 风险 / 待确认 / 产物 |
| 策略顾问 | **10 行** | 结论 / 建议 / 风险 / 待确认 |
| 独立督导 | 见 `docs/audit/TEAM.md` | 报告 40 行六节等 |

**超额申请（唯一例外通道）**：需要更长时，汇报首行写 `申请 +N 行：<原因>`；审批人＝统筹主持；单次最多 +20 行；同一职位连续 3 次申请 → 改默认上限，而不是每次都批；申请只对本次有效。

## 三·八、跨会话同步预算

1. **常态只留统筹主持一个常驻会话**；独立督导、组织规划、策略顾问按需开启、用完即结。
2. **跨会话请求只走方案箱（`docs/org/REQUEST.md`）+ 一句口令**；回执 ≤10 行，只回**提交号 + 结论 + 产物路径:行号**，不复述过程。
3. **同一触发点每个会话 ≤1 轮消息**，禁止回执往返；需要澄清的一次写进 `REQUEST.md`。**例外**：出现新事实 / 新裁定允许 1 次追加回执，首行标「新事实」。
4. 请求必须带**事实快照**（HEAD、工作树状态、相关提交号），防止陈旧转达。

边界：审查报告按 B 队手册；同步回执按本节；单会话内汇报按三·七。

## 四、审查（B 队执行，A 队只读）

**触发（命中任一）**：里程碑 / 版本切换；每累计 **3 个功能批次**；冷却到期；P0 / T3 / T6 即时；组织冲突；用户点名。

**冷却**：两次完整审查间隔 ≥7 天；冷却期内只登记不启动（P0/T6 例外）；用户可书面授权突破并在 `docs/audit/AUDIT_LOG.md` 留痕。**交接前须有一次审查**（T5），否则需用户书面豁免，结论标「降级采信」。

**报告**：≤40 行六节 + 整改清单 ≤5 条（超 5 条说明流程崩了，先改流程）；整改**并入下一功能批**，只有 P0 立即单独处理。

## 五、权限矩阵与仲裁

每一类范围只有一个写者（详见 §一 写入范围）；撞车与争议处理：

1. 同一文件同时只允许一个写者；撞车时后到者停手，报告统筹主持。
2. 归属争议：组织规划出结论 → 统筹主持拍板。
3. 跨队文件（`docs/audit/AUDIT.md`、`docs/audit/AUDIT_LOG.md`、`docs/audit/**`）：A 队只读，改动必须经统筹主持转达独立督导。
4. 一次性授权（临时让非 owner 改文件）必须留痕：日期 / 授权人 / 范围。
5. 优先级冲突：功能优先；文档改动并入批次，不单独插队。
6. 统筹主持保留直接修改权，但改后必须在 `HANDOFF` 留痕，避免与助理撞车。
7. 组织规划**只写不提交**；提交与推送一律归助理。

## 六、生命线与交接

- 硬指标 → 脚本：`node tools/session_health.mjs` 与 `node tools/token_report.mjs --json`；**脚本判红的会话自动交接，不商量**。
- 外部巡检 → **独立督导每天一次**（并入成本巡检）：标「应交接」的会话与数字，报统筹主持 + 用户。
- 最终拍板 → **用户**：可随时强制换会话，也可决定暂不换。
- 具体阈值与前置检查见 `docs/HANDOVER.md`。

## 七、度量

由脚本生成到 `docs/generated/METRICS.md`（**不要手改**）。保留 8 项：docs 提交占比、CI 首过率、打回率、**复发率（唯一硬指标）**、交接触发次数、空回复次数、转达失真次数、超线会话数。

- `docs` 提交 **每批 ≤1 个**；占比 >50% 触发复盘。
- 不设死 token 红线，先监控 2 周再定。

## 八、失败模式

| 现象 | 处理 |
|---|---|
| 文档反客为主（docs 占比 >50%） | 每批 ≤1 个 docs 提交，超了当场复盘 |
| 人工转达失真 | 请求必带事实快照；回执只给结论与路径 |
| 空回复 | 1 次告警 + 压缩；连续 2 次交接 |
| 会话膨胀 | 助理每批新开、组织规划每任务新开 |
| 双身份 | 越位即交接换会话 |
| 批次太大（>1 天） | 拆批 |
| 门禁红硬推 | 整批停，不推半成品 |
| 考官打回 2 次 | 停手换任务或换思路，不硬催 |
| 整改 >5 条 | 先改流程再干活 |
| 整改变插队 | 并入下一功能批，只有 P0 单开 |
| 热修跳过复核 | 必须留痕 `INCIDENTS`，事后补审 |
| 发布后发现问题 | 停发 + revert + 记 INCIDENTS + 更新 CHANGELOG |
| 复盘只写不跟进 | 失败样本进 INCIDENTS / RETROSPECTIVE，下批验收对照 |
| 批次记录缺失 | `docs/BATCHES.md` 每批一条，缺了不算完成 |
| 半搬半留 | 迁移同批完成，不留过渡态 |
| 提纲未确认就细化 | 返工，记入失败样本 |
