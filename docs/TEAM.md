> 审计 / 督导归 A 队（用户 2026-11-14 拍板）：B 队旧编制停设，审计督导子会话卡见 `docs/roles/a/supervisor.md`；旧 B 队手册 `docs/audit/TEAM.md` 仅作历史存档、只读。
> **2026-11-13 重建版**：依据用户逐项核对结果与 `docs/org/PLAN-20261113-4.md`（重建总方案）。
> 团队是**会话级**的：成员挂在发起它们的会话上，换会话不继承；新会话按本手册 §二 重建。

## 〇、三条铁律

1. **单会话单身份**：一个会话只戴一顶帽子；宿主身份 ≠ 职位。做了不属于本职位的事（派活 / 提交推送 / 指挥成员）即算越位 → 交接换新会话，不在原地继续。
2. **中文职位名沟通**：文档、交接、汇报一律用中文职位名；英文实例名只出现在 `spawn_teammate` / `send_message`。
3. **一个职位一个活跃实例**；换实例名只改本手册映射表，文档不动。

- **同名 teammate 会被复用（不新开）**：每批应换实例名（如本批 `assistant2`）或先结束旧会话，避免继承旧上下文（实测：复用会话本批花 16.7M）。成本归因读会话 descriptor label，`spawn_teammate` 的 `description` 以中文职位名开头（如「助理：…」），否则 `token_report` 记「未知职位」。
- **助理**：每批新开（目的是延长代理人 / 承包商寿命，不许跨批累积）。
- **工匠**：本期 1 名；下一期经「当期组织规划 + 用户」共同分析后最多再 +1（总数 ≤2）。

- **组织规划**：两个子代理只在提纲经用户确认后开，用完即关，同一时间最多 2 个。
- 退役名：`builder`、`verifier`、`steward` 永久禁用（历史文档不回改）。
- **用户核对的重建/迁移例外**：一次多文件、跨角色的改动（如 2026-11-13 重建 P0）须经用户逐项确认，并在 `docs/BATCHES.md`（或 `HANDOFF`）留痕：日期 / 授权人 / 范围。例外不改变默认的「单文件单写入者」。

## 二、重建步骤（新会话，可直接复制）

> 你是**代理人**（A，`proxy`）：唯一用户对接，写合同与验收结论、只抽查机械项；不读 diff / 构建日志 / 长文档。合同制见 §三·十，现行流程见 §三·十一 / §三·十二。

开工自检三连（任一不满足先补，不开工）：
1. `git status --short` 为空
2. `git rev-list --count origin/master..HEAD` = 0
3. `python3 tools/gen_files_index.py --check` = 0

> **策略顾问**：用户点名开。先读 `docs/HANDOFF.md`、`docs/TEAM.md`、`docs/roles/org/advisor.md`；
> 只读、≤10 行汇报；单次 >10 轮或完成即关，不累积上下文。

## 三·八、跨会话同步预算

1. **常态只留代理人一个常驻会话**；承包商按合同开、审计督导 / 组织规划 / 策略顾问按需开启、用完即结。
2. **跨会话请求只走方案箱（`docs/org/REQUEST.md`）+ 一句口令**；回执 ≤10 行，只回**提交号 + 结论 + 产物路径:行号**，不复述过程。
3. **同一触发点每个会话 ≤1 轮消息**，禁止回执往返；需要澄清的一次写进 `REQUEST.md`。**例外**：出现新事实 / 新裁定允许 1 次追加回执，首行标「新事实」。
4. 请求必须带**事实快照**（HEAD、工作树状态、相关提交号），防止陈旧转达。

边界：审计报告按 `docs/audit/AUDIT.md` 与 `docs/roles/a/supervisor.md`；同步回执按本节；单会话内汇报按三·七。

## 三·十、合同制（2026-11-14 转常设）

> 来源：2026-11-13 试点 2 个合同（C1/C2）均 accepted + 2026-11-14 用户拍板补账并转常设。合同盒 `docs/contracts/`；本节为唯一真源，角色卡见 `docs/roles/a/proxy.md`、`contractor.md`。

- **角色**：A＝`proxy`（代理人）：**唯一用户对接**，写合同与验收结论；B＝`contractor`（承包商）：**只读合同执行**，不写合同、不改验收口径；B 的成员沿用助理 / 工匠 / 考官（分工同 §一）。
- **合同盒与运行态**：合同 spec 入 `docs/contracts/C<id>-<slug>.md`；运行态 `.pilot/<id>/`（`status.json`、`result.md`、成本快照）已 gitignore，不入库。
- **状态机**：`open → claimed → green | blocked → accepted`；`status.json` 含 `base` / `claimedAt` / `commit` / `session` / `accepted`（验收记录），A 置 accepted。
- **授权**：B 按合同 §8 写入范围动态授权写代码与台账；范围外改动必须先扩合同，不得夹带。
- **交接**：手动转达句，或 watcher（`while [ ! -f .pilot/<id>/inbox.ready ]; do sleep 5; done`）。前提：App「后台运行」开启、引擎会话存活、同一触发点每会话 ≤1 轮；属 `HANDOVER` §二.8 豁免项，交接前 kill 并写「watcher 已 kill / 接管命令」；watcher 不可用则用口令兜底（重发转达句）。
- **每批必带（缺一不算完成）**：`docs/BATCHES.md` 一行（备注 `合同:<id>`）+ `tools/test_results.json` 同步 + `FILES` 重生成；`HANDOFF` 在批次收尾 / 交接前更新，**不要求每批改**。
- **B 侧提交前自检（缺一不得提交）**：B 提交前必须跑 `tools/contract_check.py --contract … --status …`，并完成台账自检（`tools/test_results.json` 同步 / `docs/BATCHES.md` 合同号 / `FILES` 重生成）；任一不过先修再提交，不得 `--no-verify` 绕过或无台账提交。
- **验收（C8 v1.8 收窄）**：机械项写「命令 + 期望值」；判断项写来源与依据；真机项写步骤 + 证据；**A 只读回执与证据 + 至多 1–2 条只读抽验，不跑测试 / 构建 / 写文件**；不读 diff / 构建日志 / 长文档，执行与取证一律由 B 落。
- **预算**：回执 ≤10 行 / 合同 ≤60 行 / **单位 ≤3 批（每批 ≤1 天；超 3 批拆合同）**。
- **成本判据（双判据，唯一口径）**：每批增量 ≤ 基线×0.85 **且** ≤30M/批；基线取开工前当日窗口实测 ÷ 窗口内批次数（不含本批）；`cost-after` 必须在 A 置 accepted 后取（与真机验收对齐）；成本快照存 `.pilot/<id>/cost.json`（`{windowTotal,baselinePerBatch,delta,perBatch,threshold}`）。
- **回滚顺序**：先 `git revert` 代码批次 → 再 revert 对应 docs 批次 → 最后 `rm -rf .pilot/`（避免 `BATCHES` / `FILES` 冲突）。
- **v1.1 增补（2026-11-14 用户拍板固化）**：
  - **编号与归档**：试点 C1/C2 标「样本」；正式合同从 **C3** 起；合同文件平铺保留，按 docs 归档规则（30 天 / 同主题 3 份）盘点。
  - **A 寿命**：>50 轮或压缩 ≥1 → 交接。
  - **B 寿命**：默认每合同新开；同合同段复用 ≤3 合同或 >30 轮即轮换；accepted 且推送后关闭。
  - **并发**：同一时间只允许 1 个 open 合同（A 负责检查）。
  - **合同粒度**：可含 ≤3 批，验收按批分列；>3 批拆合同。
  - **交接默认 watcher**（需 App「后台运行」常开）；掉线用口令兜底（重发转达句）。
  - **度量 2 项（唯一口径）**：合同一次通过率＝首轮 accepted 占比（分母=accepted 合同；<70%→复盘）；每合同成本＝accepted 合同 perBatch 均值（超 30M 或基线×0.85 记超）；数据源 `.pilot/*/status.json`、`.pilot/*/cost.json`；§七 8 项仍为权威，本节只给数据源，不改 §七。

## 三·十一、简化流程 v1.2（2026-11-14 用户拍板）

> 目标：治理 / 协调成本砍 40%–50%（今日治理约 59M / 78M）。本节是现行治理流程；与 §三主流程冲突时以本节为准。

- **单批单提交 + 自查表**：一个治理批只开 **1 助理 + 1 考官**；**治理批默认 1 条 docs（+1 tools）；功能批仍按 §七 ≤3 条/批；「单批单提交」指不拆批、不二次 amend**，超 1 条 docs 须在 `BATCHES` 备注留痕；提交前助理必须跑自查表，并在回执附结果——
  ① **事实**：`git log -1`、`git rev-list --count origin/master..HEAD`、`git status --short` 为空；
  ② **台账**：`docs/BATCHES.md` 本批行、`tools/test_results.json` 已同步、`docs/generated/FILES.md` 已重生成；
  ③ **索引**：`python3 tools/gen_files_index.py --check` = 0；
  ④ **门禁**：`tools/precommit_check.sh --scope <路径>` 通过。
  **禁止同批二次 amend**：一次写对；返工＝失败样本，记 `BATCHES` 备注（不靠 amend 擦痕迹）。
- **考官三查**：固定只查「**事实真实性 / 引用一致性 / 越权范围**」+ **抽 1 条命令复跑**；**不重跑**全量测试 / 索引 / `METRICS`（助理已跑并附输出）；只认**阻断项**；建议项由**审计督导子会话或代理人**登记 `docs/audit/ACTIONS.md`（该目录已归 A 队），A 队侧同时写 `BATCHES` 备注；并入下批，**不阻塞推送**。
- **台账脚本化**：提交前必跑 `python3 tools/batch_facts.py`（事实快照）与 `python3 tools/batch_close.py --batch "<批次名>" --dry-run`（台账收尾检查 / `BATCHES` 行草稿）；**缺一不得提交**。
  - 参数速查：`batch_facts --full`＝附 `METRICS --check`（联网耗时）；`batch_close --contract <id>`＝校合同 accepted / `contract_check`、`--regen`＝重生成 `FILES` / `METRICS`、`--run-tests`＝实跑测试核数、`--dry-run`＝默认只打印不写文件。
- **治理节奏**：治理批每周 / 每功能批 **≤1 次**，小修不单开（攒进下一功能批）；**B 侧小合同（≤3 文件改动）默认不 spawn 助理 / 工匠**，B 直接执行 + 考官 1 个（确需 spawn 则 `result.md` 说明理由；见 `docs/roles/a/contractor.md`）。

## 三·十二、v1.3 token 预算（2026-11-14 用户拍板）

> 目标：下一批 A ≤5M/批、真机 ≤2 turn/≤5 行回执、每合同成本有数。与 §三·十 / §三·十一 并用，冲突时以本节为预算细则、验收口径仍按合同 §7。

- **裁决会话（A / B）**：**0 截图、0 长文**（不读 diff / 构建日志 / 长文档）；证据**只给路径**，要细节让执行会话回贴；A 裁决每批目标 **≤5M token**。

## 四、审查（A 队：审计督导子会话执行，代理人对用户负责）

> **归属（用户 2026-11-14 拍板）**：审计 / 督导归 A 队——代理人按需 spawn 一次性审计督导子会话（fresh、只读，见 `docs/roles/a/supervisor.md`），按 `docs/audit/AUDIT.md` 触发；B 队原独立督导 / 审查员 / 成本管理员停设，职责转 A 队。

**触发（命中任一）**：里程碑 / 版本切换；每累计 **3 个功能批次**；冷却到期；P0 / T3 / T6 即时；组织冲突；用户点名。

**冷却**：两次完整审查间隔 ≥7 天；冷却期内只登记不启动（P0/T6 例外）；用户可书面授权突破并在 `docs/audit/AUDIT_LOG.md` 留痕。**交接前须有一次审查**（T5），否则需用户书面豁免，结论标「降级采信」。

**报告**：≤40 行六节 + 整改清单 ≤5 条（超 5 条说明流程崩了，先改流程）；整改**并入下一功能批**，只有 P0 立即单独处理。

## 五、权限矩阵与仲裁

每一类范围只有一个写者（详见 §一 写入范围）；撞车与争议处理：

1. 同一文件同时只允许一个写者；撞车时后到者停手，报告代理人。
2. 归属争议：组织规划出结论 → 代理人拍板。
3. 审计文件（`docs/audit/AUDIT.md`、`docs/audit/AUDIT_LOG.md`、`docs/audit/**`）：已归 A 队，改动由代理人裁定并落盘（本批不改其正文）。
4. 一次性授权（临时让非 owner 改文件）必须留痕：日期 / 授权人 / 范围。
5. 优先级冲突：功能优先；文档改动并入批次，不单独插队。
6. 代理人保留直接修改权，但改后必须在 `HANDOFF` 留痕，避免与助理撞车。
7. 组织规划**只写不提交**；提交与推送一律归助理。

## 六、生命线与交接

- 硬指标 → 脚本：`node tools/session_health.mjs` 与 `node tools/token_report.mjs --json`；**脚本判红的会话自动交接，不商量**。
- 外部巡检 → **审计督导子会话每天一次**（并入成本巡检）：标「应交接」的会话与数字，报代理人 + 用户。

## 七、度量

由脚本生成到 `docs/generated/METRICS.md`（**不要手改**）。8 项定义与阈值（2026-11-13 定）：

| # | 指标 | 定义 / 数据源 | 类型 | 阈值 → 动作 |
|---|---|---|---|---|
| 1 | docs 提交占比 | docs 提交 / 总提交（按批窗口，`git log`） | 自动 | >50% → 复盘 |
| 2 | CI 首过率 | 每提交首次构建绿的比例（CI run） | 自动 | <70% → T4 |
| 3 | 打回率 | 考官判「不可发布」次数 / 复核次数（`BATCHES`） | 自动 | >30% → T4 |
| 4 | 窗口内新增复发数 | 窗口内 `history/INCIDENTS.md` 标「（复发）」条数；窗口起点＝上次完整审查完成时间 | 自动（未实现前人工） | >0 → T4 硬触发 |
| 5 | 交接触发次数 | 每窗口因阈值换会话次数（`HANDOFF` / 巡检记录） | 人工 | >2/窗口 → 复盘 |
| 6 | 空回复次数 | `session_health`（只有推理、无正文） | 自动 | ≥1 告警+压缩；连续 2 次 → 交接 |
| 7 | 转达失真次数 | 事实快照/回执与仓库不符处，记 `BATCHES` 备注，审计督导审查时核 | 人工 | >0 → 复盘 |
| 8 | 超线会话数 | `token_report --json` 中 >100 轮的会话数 | 自动 | >0 → 告警 |

- **每项必须标「自动 / 人工 / 无数据」**；无数据不默认 0、不默认红（沿用 A-22 原则）。
- **复发判据（2026-11-13 用户拍板，2026-11-19 下次审查前生效）**：**窗口内新增复发数 > 0** 才触发 T4；
  窗口＝**上次审查之后**；只数「条目日期 ≥ 窗口起点」且标「（复发）」的条目；旧窗口条目（如 INC-007）不计入。
- **复盘触发（任一命中即写复盘件）**：docs 占比 >50% / 打回率 >30% / 新增复发 >0 / 转达失真 >0 /
  同一问题打回 2 次 / P0 / 连续两个窗口都有新增复发（审计督导附加条款）。
- **复盘件**：`docs/history/RETROSPECTIVE-<YYYYMMDD>.md`，必含「现象 / 根因 / 对策 / 验收 / 归属」；缺件该批不算完成（§八）。
- **分工**：定义归组织规划（本节）；`tools/metrics.py` 与 `METRICS` 模板归助理；数字与复盘件由审计督导子会话审查时核。
- **实现前口径**：脚本未支持前，按本表人工判定，并在报告注明「脚本未支持，人工判定」。
- `docs` 提交 **每批 ≤3 条**（同一会话 ≤1 条）；占比 >50% 触发复盘；超 3 条只复盘、不阻断（用户 2026-11-13 调整，原为 ≤1）。**一次授权合批**（如「补账+固化」）允许同会话 2 条 docs，须在 `BATCHES` 留痕；常规仍 ≤1 条/会话。
- 不设死 token 红线，先监控 2 周再定。

## 八、失败模式

| 现象 | 处理 |
|---|---|
| 文档反客为主（docs 占比 >50%） | 每批 ≤3 条 docs 提交（同一会话 ≤1 条）；超了只复盘、不阻断（2026-11-13 起，原 ≤1） |
| 人工转达失真 | 请求必带事实快照；回执只给结论与路径 |
| 空回复 | 1 次告警 + 压缩；连续 2 次交接 |
| 会话膨胀 | 助理每批新开、组织规划每任务新开 |
| 双身份 | 越位即交接换会话 |
| 批次太大（>1 天） | 拆批 |
| 门禁红硬推 | 整批停，不推半成品 |
| 考官打回 2 次 | 停手换任务或换思路，不硬催 |
| 整改 >5 条 | 先改流程再干活 |
| 整改变插队 | 并入下一功能批，只有 P0 单开 |
| 热修跳过复核 | 必须留痕 `INCIDENTS`，事后补审 |
| 发布后发现问题 | 停发 + revert + 记 INCIDENTS + 更新 CHANGELOG |
| 复盘只写不跟进 | 失败样本进 INCIDENTS / RETROSPECTIVE，下批验收对照 |
| 复盘件缺失（触发命中却无 `RETROSPECTIVE-<日期>.md`） | 该批不算完成，补写后再验收 |
| 批次记录缺失 | `docs/BATCHES.md` 每批一条，缺了不算完成 |
| 半搬半留 | 迁移同批完成，不留过渡态 |
| 提纲未确认就细化 | 返工，记入失败样本 |
