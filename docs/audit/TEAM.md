# 督导团队手册（B 队，独立于 A 队）

> **A 队手册见 `docs/TEAM.md`**（两本同名手册互相指认）。

> 督导团队**不属于** A 队（统筹主持/助理/工匠/考官），是平行的一支：
> 自己有主会话、自己管成员、只跟 A 队的统筹主持对接。
> 两边主会话都不干实际审查工作，只做任务流与成员管控。
>
> ⚠️ **本手册的参数都是默认值，不是铁律**：首次启动由独立督导与用户逐项确认；
> 之后要改，先跟用户谈，再改本文件。

## 一、编制（3 人）

| 职位 | 默认实例名 | 职责 | 写入范围 |
|---|---|---|---|
| **独立督导** | `audit-lead` | 读请求、派活、汇总报告、写台账、成本 + 轮次巡检 | `docs/audit/AUDIT.md`、`docs/audit/AUDIT_LOG.md`、`docs/audit/**`、`docs/roles/b/**`（对齐 `docs/TEAM.md` §一） |
| **审查员** | `audit-inspector` | 按 `docs/audit/AUDIT.md` 做流程审查，出结论 | **无**（只读；报告以**文本返回**独立督导，由独立督导落盘） |
| **成本管理员** | `audit-cost` | 跑 token 统计、看趋势、写成本报告 | `docs/audit/`（`COST-*.md`） |

**只读边界**：B 队不写 `native-emu/**`、不改 A 队的 `docs/`；自有件仅 `docs/audit/AUDIT.md`、`docs/audit/AUDIT_LOG.md`、`docs/audit/**`、`docs/roles/b/**`。不跑构建、不碰凭据。

> **2026-11-13 职位改名（用户定）**：督导主持→**独立督导**、主持→**统筹主持**、组织架构师→**组织规划**；
> 成员职位（审查员 / 成本管理员）与实例名不变，队名「督导团队」保留；历史台账（`AUDIT_LOG.md`、`REPORT-*`、`COST-*`）不回改。

## 二、与 A 队的接口

| 方向 | 内容 | 载体 |
|---|---|---|
| A → B | 审查请求（窗口/重点/要看的文件/触发条件） | `docs/audit/REQUEST.md`（A 队统筹主持写） |
| B → A | 审查报告（结论/证据/整改/元审查） | `docs/audit/REPORT-<YYYYMMDD>.md` |
| B → A | 成本巡检报告 | `docs/audit/COST-<YYYYMMDD>.md` |
| B → A | 审查台账（谁审的、结论、整改是否闭环） | `docs/audit/AUDIT_LOG.md`（B 队写，A 队只读） |
| B → A | **整改建议清单（可执行、带依据/owner/期限/状态）** | `docs/audit/ACTIONS.md`（B 队写，A 队只读） |
| B ↔ 组织规划 | 审查机制意见：组织规划写 `docs/org/`，**由统筹主持转达** B 队；B 队不改组织规划文档，组织规划不改 B 队三张角色卡 | `docs/org/`（组织规划写）+ 统筹主持转达 |

**A 队只读**：`AUDIT_LOG.md`、`ACTIONS.md` 由 B 队维护，A 队不得修改，只能在自己的 TODO 里跟进整改。
**B 队只读**：不改 A 队 `docs/`（`AUDIT_LOG.md` 除外）、不改 `docs/org/`；B 队改 A 队文档属越权（唯一一次性例外见第八节补充认定）。

## 三、运行节奏

1. A 队统筹主持触发条件成立 → 写 `REQUEST.md` → 通知独立督导（用户在会话间转达或粘贴）
2. 独立督导派给审查员；审查员按 `AUDIT.md` 六节输出（40 行上限，超额需申请）
3. 独立督导汇总 → 写 `REPORT-<日期>.md` + 追加 `AUDIT_LOG.md`
4. **两次审查之间**：成本管理员**每天**巡检一次 token，写 `COST-<YYYYMMDD>.md`（用户 2026-11-12 定）
5. 成本异常（单批 +30%、职位占比突增、重复读上升）→ 报独立督导 → 可触发提前审查

## 四、审查请求模板（A 队填）

```markdown
# 审查请求 YYYY-MM-DD
- 触发条件：T2（每 3 个批次）/ T3（事故）/ T6（安全）…
- 审查窗口：<批次名或提交范围>
- 重点看：
  1. …
  2. …
- 已知争议：（A 队自己觉得可能被误判的地方）
- 附件：<报告文件路径>
```

## 五、审查报告模板（B 队填，**六节 ≤40 行**）

```markdown
# 审查报告 YYYY-MM-DD（窗口：…，HEAD …）
## 一、结论：通过 / 有条件通过 / 不通过 —— 一句话理由
## 二、证据：表（时间 | 文件:行号 / 命令 | 事实（A–H 类））
## 三、整改项：≤5 条，每条带 owner + 期限（超 5 条 → 先改流程）
## 四、成本：≤5 行（最贵职位 / 最贵批次 / 一条建议；只报告不设红线）
## 五、下次复查点：3–5 条可核验项
## 六、元审查：触发条件（偏敏感 / 偏宽松 / 合适 + 量化改法）/ 督导流程 / 判定权
```

## 六、成本巡检模板（成本管理员填，≤10 行）

```markdown
# 成本巡检 YYYY-MM-DD
- 本周总量：X 亿（input / output / cacheRead 分列）
- 最贵职位：<职位，占比>
- 环比：+X%（是否超 30% 阈值）
- 重复读：<文件×次数>
- 异常：<有/无，具体>
- 建议：<一条>
```

## 七、边界与红线

- B 队**不评价代码风格、不审单个 bug**（那是考官的事）
- B 队**不改 A 队的规范**，只能提「规范补丁建议」
- 审查结论对 A 队有约束力：**不通过 = 暂停发布**，直到整改复查
- 审查频率仍按 `AUDIT.md` 的 T1–T6 + 7 天冷却；**成本巡检是每天，不是每天审查**，别把两者混为一谈

## 十、成员 token 核算（用户 2026-11-12 追加，每次成员工作结束必做）

- **谁做**：独立督导本人。核算本身也要花 token，为核算再开一个会话是倒挂。
- **什么时候**：每名成员（审查员 / 成本管理员）一次工作结束、报告交回后立刻算，不等批次结束。
- **数据源**：`~/.dsh/sessions/<工作区>/<会话>/session.v4.jsonl.zstd` 的 `data.usage`
  （`inputTokens / outputTokens / cacheReadTokens / cacheWriteTokens / totalTokens`）；
  成员用 `subagent/descriptor.label` 认。首轮实测：审查员 `8dcfe228`、成本管理员 `7d8bd16f`。
- **取数**：`node tools/token_report.mjs --json` 出按职位/按会话汇总；**当前脚本没有「按成员单列」开关**，
  会话级要按 `label + 起止时间` 临时拆。建议助理给脚本加 `--by-session`（整改候补，不单独立项）。
- **单价**（元 / 百万 tokens，模型 `deepseek-flash`，取 2026-11-12 官方页）：

  | 项 | 空闲时段 | 高峰时段 |
  |---|---|---|
  | 输入·缓存未命中 | 1 元 | 2 元 |
  | 输入·缓存命中 | 0.02 元 | 0.04 元 |
  | 输出 | 4 元 | 8 元 |

  高峰＝北京时间周一至周五 9:00–12:00、14:00–18:00（不含法定节假日），其余为闲时。
  **单价会变**：每次核算以 <https://api-docs.deepseek.com/zh-cn/quick_start/pricing/> 当日为准，
  并在记录里写明用了哪档价、几点跑的。
- **算法**：`cost = input×未命中价 + cacheRead×命中价 + output×输出价 + cacheWrite×0`
  （DeepSeek 不收缓存写费）。因 `totalTokens = input + output + cacheRead + cacheWrite`，
  `inputTokens` 已是**未命中部分**，不要再把 cacheRead 从 input 里扣一次。
- **记账**：写入本轮 `docs/audit/AUDIT_LOG.md` 的「成员开销」小节（或当日 `COST-*.md`），保留 4 位小数、单位元，
  并注明单价档位与时间。首轮实测见 AUDIT_LOG「2026-11-12 成员开销」。

  期限、状态；**每轮新增 ≤5 条**（超了说明流程崩，先做减法）。
- **送达**：B 队不能直接给 A 队会话发消息，跨会话只有两条通道——
  ① 文件（A 队自己读 `ACTIONS.md`）；② **用户转达**（统筹主持与独立督导之间对接的唯一人工通道）。
  所以独立督导每次汇报都要点明「本轮新增/变更了哪几条」，由用户带进 A 队会话。
- **回执**：A 队**不回执**（第八节第 4 项约定）；状态由 B 队下次审查**核仓库**后更新
  （待办 → 已落地 / 部分 / 未落地），不采信口头完成。A 队直接改 `ACTIONS.md` 视为越权。
- **不替 A 队定优先级**：清单只给「建议 + 期限」；发不发版、先做哪条，由 A 队统筹主持定。

## 十二、每日巡检（2026-11-13 新增，并入成本巡检）

> 依据：`docs/TEAM.md` §六「外部巡检 → 独立督导每天一次」、`docs/HANDOVER.md` 零节与 §一（阈值）。

- **频率**：每天一次，与成本巡检同一趟，不另开一趟会话。
- **跑什么**：
  1. `node tools/session_health.mjs --json`（阈值：轮次 > 100 / 压缩 ≥ 2 / 连续 2 轮空回复；exit 1 = 应交接）
  2. `node tools/token_report.mjs --json`（全体会话轮次与 token；成本口径见第十节）
- **报告什么**：超线会话标「**应交接**」+ **会话 id** + **具体数字**（轮次 / 压缩次数 / 空回复），报**统筹主持 + 用户**。
- **边界（只判不换）**：换会话由**用户或该会话的统筹主持**执行；统筹主持不给自己判交接；硬指标 exit 1 的会话由该会话自检自动交接，不商量。
- **无数据时**：脚本跑不动或字段缺失（如压缩次数不可得）→ 写「无数据」，不猜，不得用轮次代替压缩次数下结论。
