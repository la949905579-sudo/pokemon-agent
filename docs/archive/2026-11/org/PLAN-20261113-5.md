## 一、问题

- 现行 T4（`docs/audit/AUDIT.md:14`）：CI 首过率 < 70% / 打回率 > 30% / **复发率 > 0** → 强制启动审查。
- `docs/generated/METRICS.md:57` 定义：复发率 = `docs/history/INCIDENTS.md` 中标题标「（复发）」的条目数 / 事故总数。
- 现状 1/7 → 恒 > 0 → **每轮必红**，T4 失去判别力。

## 二、用户裁定（2026-11-13）

1. 判据改为：**窗口内新增复发数 > 0** 才触发 T4。
2. 窗口＝**上次审查之后**（不使用滚动 7 天）。
3. 首过率 <70%、打回率 >30% 两个触发**保留不变**。
4. 生效时点：**2026-11-19 下次审查前**。

## 三、口径定义（提案）

- **窗口起点**：上一次完整审查的完成时间（以 `docs/audit/AUDIT_LOG.md` 最新一条完整审查记录为准）。
- **计数对象**：`docs/history/INCIDENTS.md` 中同时满足两条的条目：① 标题标「（复发）」；② 条目日期 ≥ 窗口起点。
- **不计入**：窗口起点之前的复发条目（如 INC-007，2026-11-12），仍保留在事故历史里供追溯。
- **判据**：窗口内新增复发数 **> 0** → T4 红 → 强制启动审查；= 0 → 不因此触发（其余两项照旧）。
- **边界**：若窗口起点缺失（无审查记录），按「无数据」处理，不得默认 0 或默认红，由独立督导核定。
