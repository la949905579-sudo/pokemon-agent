## 〇、三条铁律

1. **单会话单身份**：一个会话只戴一顶帽子；宿主身份 ≠ 职位。做了不属于本职位的事（派活 / 提交推送 / 指挥成员）即算越位 → 交接换新会话，不在原地继续。
2. **中文职位名沟通**：文档、交接、汇报一律用中文职位名；英文实例名只出现在 `spawn_teammate` / `send_message`。
3. **一个职位一个活跃实例**；换实例名只改本手册映射表，文档不动。

## 三·八、A↔B 同步（单文件总线，C10 v2.0）

> 来源：用户 2026-11-14 16:4x 拍板；协议真源 `.pilot/BUS-PROTOCOL.md`。A/B 各为独立主会话，用户只负责开会话、不再逐步转达。

- **单文件**：A↔B 只通过 `.pilot/BUS.md`（append-only、gitignore、不入库）通信；每段一条消息，只追加、不改历史段；写前 `flock .pilot/BUS.lock`（或单次 `>>` 追加 ≤4KB）。
- **消息格式**：`## #<seq> <YYYY-MM-DD HH:MM> from=A|B <TYPE>` + 内容 ≤10 行（路径类只给路径）。
- **TYPE**：A 发 `CONTRACT` / `ACCEPTED` / `BLOCKED` / `RELEASE_OK` / `END` / `QUERY` / `NOTE`；B 发 `NOTE` / `GREEN` / `BLOCKED` / `CLOSED` / `ACK_END` / `QUERY`。
- **B 轮询**：启动即读 `.pilot/BUS-B-state.json` 的 `lastSeen` 并轮询总线（每 15–30s 一次，单轮阻塞 ≤20 分钟，超时先回一行状态）；完成工作后**继续轮询**；收到 `END` 回 `ACK_END` 后停止。
- **处理即轮询（C10 v2 流程强制）**：B 每处理完一步必须追加总线状态并轮询；收到 `HOLD` / `STOP` **立即停手**（C10 v1 事故教训），不提交 / 不推送，按 A 指令处置。
- **A 监听**：A 用后台监听总线（**连续两次异常 → 改用户提示**）；A 不轮询，需知进展时读 BUS.md 尾部。
- **留痕**：回执 ≤10 行，只回提交号 + 结论 + 产物路径:行号；同一触发点每会话 ≤1 轮消息，需要澄清一次写进总线。

边界：审计报告按 `docs/audit/AUDIT.md` 与 `docs/roles/a/supervisor.md`；单会话内汇报按 §三·七。

## 三·十一、简化流程 v1.2（2026-11-14 用户拍板）

> 目标：治理 / 协调成本砍 40%–50%（今日治理约 59M / 78M）。本节是现行治理流程；与 §三主流程冲突时以本节为准。

- **单批单提交 + 自查表**：一个治理批只开 **1 助理 + 1 考官**；**治理批默认 1 条 docs（+1 tools）；功能批仍按 §七 ≤3 条/批；「单批单提交」指不拆批、不二次 amend**，超 1 条 docs 须在 `BATCHES` 备注留痕；提交前助理必须跑自查表，并在回执附结果——
  ① **事实**：`git log -1`、`git rev-list --count origin/master..HEAD`、`git status --short` 为空；
  ② **台账**：`docs/BATCHES.md` 本批行、`tools/test_results.json` 已同步、`docs/generated/FILES.md` 已重生成；
  ③ **索引**：`python3 tools/gen_files_index.py --check` = 0；
  ④ **门禁**：`tools/precommit_check.sh --scope <路径>` 通过。
  **禁止同批二次 amend**：一次写对；返工＝失败样本，记 `BATCHES` 备注（不靠 amend 擦痕迹）。
- **考官三查**：固定只查「**事实真实性 / 引用一致性 / 越权范围**」+ **抽 1 条命令复跑**；**不重跑**全量测试 / 索引 / `METRICS`（助理已跑并附输出）；只认**阻断项**；建议项由**审计督导子会话或代理人**登记 `docs/audit/ACTIONS.md`（该目录已归 A 队），A 队侧同时写 `BATCHES` 备注；并入下批，**不阻塞推送**。
- **台账脚本化**：提交前必跑 `python3 tools/batch_facts.py`（事实快照）与 `python3 tools/batch_close.py --batch "<批次名>" --dry-run`（台账收尾检查 / `BATCHES` 行草稿）；**缺一不得提交**。
  - 参数速查：`batch_facts --full`＝附 `METRICS --check`（联网耗时）；`batch_close --contract <id>`＝校合同 accepted / `contract_check`、`--regen`＝重生成 `FILES` / `METRICS`、`--run-tests`＝实跑测试核数、`--dry-run`＝默认只打印不写文件。
- **治理节奏**：治理批每周 / 每功能批 **≤1 次**，小修不单开（攒进下一功能批）；**B 侧小合同（≤3 文件改动）默认不 spawn 助理 / 工匠**，B 直接执行 + 考官 1 个（确需 spawn 则 `result.md` 说明理由；见 `docs/roles/a/contractor.md`）。

## 七、度量

由脚本生成到 `docs/generated/METRICS.md`（**不要手改**）。8 项定义与阈值（2026-11-13 定）：

| # | 指标 | 定义 / 数据源 | 类型 | 阈值 → 动作 |
|---|---|---|---|---|
| 1 | docs 提交占比 | docs 提交 / 总提交（按批窗口，`git log`） | 自动 | >50% → 复盘 |
| 2 | CI 首过率 | 每提交首次构建绿的比例（CI run） | 自动 | <70% → T4 |
| 3 | 打回率 | 考官判「不可发布」次数 / 复核次数（`BATCHES`） | 自动 | >30% → T4 |
| 4 | 窗口内新增复发数 | 窗口内 `history/INCIDENTS.md` 标「（复发）」条数；窗口起点＝上次完整审查完成时间 | 自动（未实现前人工） | >0 → T4 硬触发 |
| 5 | 交接触发次数 | 每窗口因阈值换会话次数（`HANDOFF` / 巡检记录） | 人工 | >2/窗口 → 复盘 |
| 6 | 空回复次数 | `session_health`（只有推理、无正文） | 自动 | ≥1 告警+压缩；连续 2 次 → 交接 |
| 7 | 转达失真次数 | 事实快照/回执与仓库不符处，记 `BATCHES` 备注，审计督导审查时核 | 人工 | >0 → 复盘 |
| 8 | 超线会话数 | `token_report --json` 中 >100 轮的会话数 | 自动 | >0 → 告警 |

- **每项必须标「自动 / 人工 / 无数据」**；无数据不默认 0、不默认红（沿用 A-22 原则）。
- **复发判据（2026-11-13 用户拍板，2026-11-19 下次审查前生效）**：**窗口内新增复发数 > 0** 才触发 T4；
  窗口＝**上次审查之后**；只数「条目日期 ≥ 窗口起点」且标「（复发）」的条目；旧窗口条目（如 INC-007）不计入。
- **复盘触发（任一命中即写复盘件）**：docs 占比 >50% / 打回率 >30% / 新增复发 >0 / 转达失真 >0 /
  同一问题打回 2 次 / P0 / 连续两个窗口都有新增复发（审计督导附加条款）。
- **复盘件**：`docs/history/RETROSPECTIVE-<YYYYMMDD>.md`，必含「现象 / 根因 / 对策 / 验收 / 归属」；缺件该批不算完成（§八）。
- **分工**：定义归组织规划（本节）；`tools/metrics.py` 与 `METRICS` 模板归助理；数字与复盘件由审计督导子会话审查时核。
- **实现前口径**：脚本未支持前，按本表人工判定，并在报告注明「脚本未支持，人工判定」。
- `docs` 提交 **每批 ≤3 条**（同一会话 ≤1 条）；占比 >50% 触发复盘；超 3 条只复盘、不阻断（用户 2026-11-13 调整，原为 ≤1）。**一次授权合批**（如「补账+固化」）允许同会话 2 条 docs，须在 `BATCHES` 留痕；常规仍 ≤1 条/会话。
- 不设死 token 红线，先监控 2 周再定。

## 八、失败模式

| 现象 | 处理 |
|---|---|
| 文档反客为主（docs 占比 >50%） | 每批 ≤3 条 docs 提交（同一会话 ≤1 条）；超了只复盘、不阻断（2026-11-13 起，原 ≤1） |
| 人工转达失真 | 请求必带事实快照；回执只给结论与路径 |
| 空回复 | 1 次告警 + 压缩；连续 2 次交接 |
| 会话膨胀 | 助理每批新开、组织规划每任务新开 |
| 双身份 | 越位即交接换会话 |
| 批次太大（>1 天） | 拆批 |
| 门禁红硬推 | 整批停，不推半成品 |
| 考官打回 2 次 | 停手换任务或换思路，不硬催 |
| 整改 >5 条 | 先改流程再干活 |
| 整改变插队 | 并入下一功能批，只有 P0 单开 |
| 热修跳过复核 | 必须留痕 `INCIDENTS`，事后补审 |
| 发布后发现问题 | 停发 + revert + 记 INCIDENTS + 更新 CHANGELOG |
| 复盘只写不跟进 | 失败样本进 INCIDENTS / RETROSPECTIVE，下批验收对照 |
| 复盘件缺失（触发命中却无 `RETROSPECTIVE-<日期>.md`） | 该批不算完成，补写后再验收 |
| 批次记录缺失 | `docs/BATCHES.md` 每批一条，缺了不算完成 |
| 半搬半留 | 迁移同批完成，不留过渡态 |
| 提纲未确认就细化 | 返工，记入失败样本 |
