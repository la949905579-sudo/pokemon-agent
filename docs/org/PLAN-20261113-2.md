### 3. 最痛的三点（结论）

1. **归属分裂**：审查件三分之一在平铺层（`AUDIT/AUDIT_LOG/METRICS`，合计路径引用 69 次），三分之一在 `docs/audit/`；角色卡 A/B/第三方混放。
2. **生命周期混放**：活规范、历史快照、生成物同层；`docs/org/` 会持续增长，缺归档约定。
3. **命名边界模糊**：三组易混（HANDOFF/HANDOVER、PROJECT_PLAN/WORKPLAN/TODO、两本 TEAM 同名——后者已用「抬头+互指」缓解）。

## 二、设计原则

1. **单一真源**：每类信息只有一份权威文件（如测试数只认 `tools/test_results.json`）。
2. **按「归属 / 生命周期」分层**：A 队 / B 队 / 第三方写区分开；活 / 历史 / 生成分开。
3. **生成物与手写分离**：脚本产物集中、文件头标注、`--check` 可验。
4. **迁移成本最小**：优先加规则与索引，不轻易动高引用文件（`TEAM.md` 48 次路径引用）。
5. **旧文不改**：历史文件内容不回改；允许「移动 + 链接更新」，但历史引用以「当时路径」可读为限。
6. **与既有规范对齐**：代码侧遵循 `STRUCTURE.md` 的 P1/P2 分期，不另起一套。

## 三、方案

### 方案 A：最小整理（只补规则，不动目录）— 推荐先做

```
docs/
├── README.md          # 新增：docs 分区说明（活/历史/生成 + 归属 + 命名 + 维护者）
├── archive/           # 新增：只收新结案件（PLAN-*/REPORT-*/COST-* 满期后移入）
├── TEAM.md …（21 份不动）
├── roles/  audit/  org/（不动）
```

- **改什么**：新增 `docs/README.md`（分区说明 + 文件头元数据约定：`归属：A队/B队/第三方 ｜ 生命周期：活/历史/生成 ｜ 维护者`，只对**新文件**生效）；新增空目录 `docs/archive/` 并在 README 写归档规则（如 PLAN/REPORT 满 30 天或同主题 >3 份时移入）；`FILES.md` 重生成（索引自动收录新文件）。
- **不改什么**：不搬任何现有文件、不改任何现有文档内容、不改命名。
- **影响谁**：A 队（新文件按约定写头）、B 队（`docs/audit/` 新文件同约定）、脚本（无）。
- **迁移成本**：**新增 1 个文件 + 1 个空目录 + 1 次 `FILES.md` 重生成**；现有 377 次路径引用 **0 改动**；搬 0 文件。
- **风险**：规则靠自觉、无机械约束；`docs/org/` 增长仍在平铺层（但 README 可约束其命名）。
- **验证**：`docs/README.md` 存在且含「活/历史/生成」三分与归档规则；`python3 tools/gen_files_index.py --check` = 0；`git diff --stat` 仅新增文件 + 生成物。
- **不采用的代价**：现状继续混放，新增文件继续无归属标注；后期搬迁成本只会随引用增长而变大。

### 方案 B：按归属重构（中等搬迁）

```
docs/
├── team/              # 两本手册集中
│   ├── A_TEAM.md      # ← docs/TEAM.md（更名）
│   └── B_TEAM.md      # ← docs/audit/TEAM.md（更名）
├── roles/
│   ├── a/             # steward.md / artisan.md / examiner.md
│   ├── b/             # audit-lead.md / audit-cost.md / auditor.md
│   └── org/           # architect.md
├── audit/             # 收全部审查件：AUDIT.md / AUDIT_LOG.md / REQUEST / ACTIONS / REPORT-* / COST-*
├── org/               # 不变（接口区）
├── living/            # 其余活规范：HANDOVER / STRUCTURE / OBSERVABILITY / NATIVE_EMU_TODO / HANDOFF / PROJECT_PLAN / WORKPLAN
├── archive/           # 历史：CHANGELOG / INCIDENTS / RETROSPECTIVE / ARCHITECTURE / NOTES
└── FILES.md METRICS.md（生成物，保持顶层 + 头标注）
```

- **改什么**：迁 13 个文件（两本 TEAM、7 张角色卡、AUDIT/AUDIT_LOG/METRICS 3 份）并改路径；`METRICS.md` 目标路径要改 `tools/metrics.py` 的 OUT；A/B 写范围、`FILES.md` 索引、角色卡中的引用同步。
- **不改什么**：文件内容（除引用行）；历史文件正文不回改。
- **影响谁**：A 队/B 队（写范围与互指）、脚本（`metrics.py` 输出路径；`gen_files_index.py` 若有硬编码路径）、CI/交接检查清单。
- **迁移成本（数字）**：13 文件搬迁；路径引用 ≈ **187 次**（TEAM 48 + audit/TEAM 33 + AUDIT 30 + AUDIT_LOG 15 + METRICS 24 + 角色卡 37）；裸名引用 ≈ **427 次**需人工甄别（多数语境可机械补全，但两本 TEAM 同名要人工判断）。合计约 **600+ 处文本触碰**，远超方案 A。
- **风险**：①两本 TEAM 刚拍板「抬头+互指」方案 1，再更名会被视为反复；②`docs/audit/` 是 B 队写范围，把 A 队维护的 `AUDIT.md`/`METRICS.md` 移进去要**B 队同意**并改角色卡写权限；③历史文件大量裸名引用（如「见 TEAM.md 三·七」）无法无脑替换。
- **验证**：`grep -rn "docs/TEAM.md\|docs/audit/TEAM.md\|docs/roles/" docs tools *.md` 旧路径 = 0（白名单除外）；`run_tests.py` 全过；`gen_files_index --check` = 0；`metrics.py` 能写新路径；交接清单更新。
- **不采用的代价**：归属分裂与 A/B 混放持续，跨队写权边界靠人记。

### 方案 C：按生命周期三分（大搬迁）

```
docs/
├── living/       # 活规范：TEAM / HANDOVER / STRUCTURE / OBSERVABILITY / AUDIT / NATIVE_EMU_TODO / HANDOFF / PROJECT_PLAN / WORKPLAN
├── history/      # 历史：AUDIT_LOG / CHANGELOG / INCIDENTS / RETROSPECTIVE / ARCHITECTURE / NOTES / audit/REPORT-* / audit/COST-* / org/PLAN-*
├── generated/    # 生成物：FILES / METRICS（脚本 OUT 改到此处）
├── roles/  audit/  org/   # 接口区保留
└── archive/      # 可选：更久的历史再下沉一层
```

- **改什么**：迁 ~20–24 个文件；`metrics.py`/`gen_files_index.py` 输出路径与索引逻辑、`FILES.md` 头说明、检查清单、两本手册的引用全改；历史文件「只移动不改正文」。
- **不改什么**：不改正文语义；不合并文件（`HANDOFF`/`HANDOVER` 等保持各自职责）。
- **影响谁**：A 队 + B 队 + 所有脚本与 CI 检查点；跨会话文档「当时路径」可读性受损。
- **迁移成本（数字）**：文件 ~20–24；路径引用 ≈ **250+ 次**；裸名引用 >500 次；脚本改动 2 个（`metrics.py`、`gen_files_index.py` 的路径/索引）；检查清单 2 份。约 **1000+ 处文本触碰**。
- **风险**：最大。历史文档被搬动后，提交信息/旧报告里的路径失效；`AUDIT_LOG` 等由 B 队维护，跨队同步成本；收益（可辨识的生命周期）与成本不成比例。
- **验证**：同方案 B + 生成物写入路径全绿；旧路径 grep = 0；CI 通过。
- **不采用的代价**：活/历史仍混放；但可先做方案 A 的分区说明缓解，不必立刻搬家。

## 四、推荐（分阶段）

**总体：先 A（立即）→ B 的「角色卡按队拆分」子集（下一 docs 批）→ 两本 TEAM 更名与 C 暂缓。**

| 阶段 | 内容 | 时点 | 验收 |
|---|---|---|---|
| **P0（立即，方案 A）** | `docs/README.md`（分区/归属/生命周期/归档规则）+ `docs/archive/` 空目录 + 新文件头元数据约定 + `FILES.md` 重生成 | 下一 docs 批（可与 F 批次并行，**无需冷却**） | README 含三分说明；`gen_files_index --check`=0；0 搬迁 |
| **P1（方案 B 子集）** | `docs/roles/` 按队拆 `a/` `b/` `org/`（7 文件，路径引用 37 次）；A/B 两队角色卡写范围同步 | 下一里程碑 / 冷却期后（≥2026-11-19，或 F 批次完成后） | 旧 `docs/roles/*.md` 路径 grep=0；测试全过；FILES --check=0 |
| **P2（方案 B 余量）** | 审查件归并（`AUDIT.md`/`AUDIT_LOG.md`/`METRICS.md` → `docs/audit/`，需 B 队同意 + 写权限更新 + `metrics.py` OUT 改动）；随后再议两本 TEAM 更名 | 再下一个里程碑，且必须经 B 队同意与用户拍板 | 写范围更新；脚本可写新路径；CI 绿 |
| **P3（不推荐现在做）** | 方案 C 整体生命周期三分 | 观察：`docs/` 文件 >50 或 `docs/org/` PLAN >6 时再评估 | — |

**理由**：方案 A 以 1 个文件换「归属/生命周期」显式化，收益/成本最高；方案 B 的价值集中在「角色卡按队拆」这一小块（37 次引用，可控），两本 TEAM 刚用抬头方案解决，不宜马上再动；方案 C 收益低、触碰面大。
