# A-21 度量落地清单（给助理）

> 归属：组织规划 ｜ 生命周期：活 ｜ 维护者：组织规划
> 来源：`docs/audit/ACTIONS.md` A-21（owner＝助理 + 组织规划）；定义与阈值已由用户 2026-11-13 确认，落 `docs/TEAM.md` §七。
> 原则：**8 项全部可见，每项标「自动 / 人工 / 无数据」；无数据不默认 0、不默认红。**

## 一、目标

`docs/generated/METRICS.md` 从「只有首过率、复发率」扩到 **8 项**，并与 `docs/TEAM.md` §七 的表一一对应。

## 二、脚本实现清单（`tools/metrics.py`）

| # | 指标 | 取数建议 | 类型 | 输出字段 |
|---|---|---|---|---|
| 1 | docs 提交占比 | 窗口内 `git log --oneline` 计数：`docs` 提交 / 总提交 | 自动 | count / total / pct |
| 2 | CI 首过率 | 现有实现（CI run 记录） | 自动 | pct |
| 3 | 打回率 | 解析 `docs/BATCHES.md` 表格「考官结论」列（不可发布 / 复核次数） | 自动 | rejected / reviews / pct |
| 4 | 窗口内新增复发数 | `docs/history/INCIDENTS.md` 中「（复发）」条目按日期过滤窗口（与 A-22 窗口过滤**同一实现**） | 自动（未实现前人工） | count / window_start |
| 5 | 交接触发次数 | 解析 `HANDOFF` 交接记录/巡检报告（人工填则标「人工」） | 人工 | count |
| 6 | 空回复次数 | `session_health.mjs` 输出（需可读的最近值或日志） | 自动 | count |
| 7 | 转达失真次数 | `docs/BATCHES.md` 备注中「转达失真」出现次数 | 人工 | count |
| 8 | 超线会话数 | `token_report --json` 中 turns > 100 的会话数 | 自动 | count |

**与 A-22 合并注意**：第 4 项与 A-22「窗口过滤」共用同一函数，**一次改 `metrics.py` 同时落两项**，避免分两次改同一文件。

## 三、`METRICS` 模板要求

每行输出：`指标名 / 值 / 类型（自动·人工·无数据）/ 阈值 / 判定（红·黄·绿·无数据）`；
无数据时值写「无数据」，判定写「无数据」，**不得省略**。

## 四、验收

1. `python3 tools/metrics.py` 生成的 `METRICS.md` 含 8 行且与 §七 表一致；
2. `python3 tools/metrics.py --check` = 0；
3. `docs/history/INCIDENTS.md` 回归：窗口起点后无新增复发时第 4 项判绿（INC-007 不计入）；
4. 抽一项人工项（五或七）确认标注为「人工」。

## 五、边界

- 本清单只给实现口径，不替代 `docs/TEAM.md` §七（唯一真源）；
- 组织规划只写不提交；脚本改动归助理，按批次提交（docs 提交每批 ≤3 条、同会话 ≤1 条）。
