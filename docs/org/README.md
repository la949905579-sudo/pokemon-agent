# docs/org/ — 组织架构师接口

> `architect`（组织架构师）是独立第三方，不常驻、按需开启；提示词见 `docs/roles/architect.md`。
> 用户 2026-11-12 确认的参数见 `docs/TEAM.md` 的「〇·五」小节。

## 接口文件

| 方向 | 载体 | 写者 |
|---|---|---|
| 主持 → 架构师 | `REQUEST.md` | 主持 |
| 架构师 → 主持 | `PLAN-<YYYYMMDD>.md` | 架构师 |

- 每次唤醒：主持先写 `REQUEST.md`（窗口 / 关注点 / 已知争议），架构师读后出方案
- 方案、组织评估、流程建议一律写成 `PLAN-<YYYYMMDD>.md`；同一天多份加后缀 `-2`、`-3`
- 落到手册 / 角色卡的结论以 `docs/TEAM.md`、`docs/roles/*.md` 为准，本目录只是过程稿

## 与 B 队（督导）的接口

- 架构师与 B 队**互不改文档**、不直接对接：涉及审查机制（`docs/AUDIT.md`、审查节奏、报告口径）的意见
  写进本目录的报告，由主持转给督导主持
- B 队载体在 `docs/audit/`（请求 / 报告 / 成本 / 台账），架构师**只读**

## 产物命名

- `PLAN-YYYYMMDD.md`：方案 / 评估 / 建议（必需）
- `REQUEST.md`：主持填的当轮请求
- 不放代码、日志、草稿附件
- 已归档：`PLAN-20261112.md` — 2026-11-12 首轮同步盘点（审查结论 / 整改实测 / 成本巡检 / 触发条件）
