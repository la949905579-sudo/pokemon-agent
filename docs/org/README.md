# docs/org/ — 方案箱（组织规划接口）

> **中文叫法：方案箱**。日常口语统一用这三个字；文件路径仍是 `docs/org/`（文件名英文规则不变）。
> `architect`（组织规划）是独立第三方，不常驻、按需开启；提示词见 `docs/roles/org/architect.md`。
> 用户 2026-11-12 确认的参数见 `docs/TEAM.md` 的「〇·五」小节。

## 方案箱规则

| 方向 | 载体 | 写者 |
|---|---|---|
| 代理人 → 组织规划 | `REQUEST.md` | 代理人 |
| 组织规划 → 代理人 | `PLAN-<YYYYMMDD>.md` | 组织规划 |

- 每次唤醒：代理人先写 `REQUEST.md`（窗口 / 关注点 / 已知争议），组织规划读后出方案
- 方案、组织评估、流程建议一律写成 `PLAN-<YYYYMMDD>.md`；同一天多份加后缀 `-2`、`-3`
- 落到手册 / 角色卡的结论以 `docs/TEAM.md`、`docs/roles/*.md` 为准，本目录只是过程稿

## 与审计督导（A 队子会话）的接口

- 组织规划与审计督导**互不改文档**、不直接对接：涉及审查机制（`docs/audit/AUDIT.md`、审查节奏、报告口径）的意见
  写进本目录的报告，由代理人转给审计督导子会话
- 审计载体在 `docs/audit/`（请求 / 报告 / 成本 / 台账，2026-11-14 起归 A 队），组织规划**只读**

## 产物命名

- `PLAN-YYYYMMDD.md`：方案 / 评估 / 建议（必需）
- `REQUEST.md`：代理人填的当轮请求
- 不放代码、日志、草稿附件
