# 复盘 2026-11-14：C7 治理小批成本超阈（21.6%）+ 一轮 blocked

> 归属：A 队 ｜ 生命周期：活（跟踪至验收项闭环） ｜ 维护者：代理人（proxy）／落盘：承包商（B）

## 一、现象（实测）

- **基线**（C7 开工前，B 沿用旧流程由 A 落）：windowTotal **182,167,266** ÷ 8 批 = **22,770,908**/批；阈值（×0.85）= **19,355,272**。
- **C7 增量**（accepted 后取）：windowTotal **205,701,383** − 182,167,266 = **23,534,117**；batches=1 → perBatch = **23,534,117**。
- **判据**：23,534,117 > 19,355,272（超 **21.6%**）；23.5M ≤ 30M/批 ✓ → 双判据未全过，METRICS #10 记超（不阻断收尾，只记数）。
- **过程异常**：C7 执行中出现 **1 轮 blocked→A 裁定→resume**（M5 判据由「<10%」修订为「<15%」），`status.json` history 4 条（claim → blocked → resume → green）。
- **归因**（`.pilot/C7/cost.json` `byRole`，窗口全量）：主会话（未标注职位）85.5M / 承包商 42.9M / 助理 39.0M / 未知职位 26.1M / 考官 11.7M / 真机 0.5M。

## 二、根因（按贡献排序）

1. **验收判据不可达（机制性，主要）**：A 起草 M5 写「未知职位 <10%」，但试点 C1/C2 两个会话 label 本身无职位词、按不造映射口径无法消除 → 首轮即 blocked，产生 **1 轮往返 + 1 次 resume**，多花一个完整回合（复算 + 合同修订 + 重新执行）。
2. **blocked→resume 多轮（显性浪费）**：同一合同先 blocked 报 A 裁定、再 resume 续做，`status.json` history 从 3 条涨到 4 条；会话生命周期被拉长，cacheRead 持续累积。
3. **A 侧长文与取证推高主会话（结构性）**：窗口内主会话（未标注职位）合计 85.5M，占 `byRole` 首位；A 起草合同 / 启动提示词 / 自测命令属于实质产出，但占比过高，与「A 只经手 / 审核」边界不符。
4. **成本快照流程仍由 A 代跑**（流程性）：C7 开工前基线由 A 手动跑 `cost_snapshot --before`，A 承担了本应 B 执行的工具操作，既占 A token 又让「A 不跑工具」的口径落空。

## 三、对策

1. **验收判据先做可达性自检**（写进 C8 起合同）：A 起草机械项后，先用只读命令（或让 B 在 claim 首步）验证「期望值能否被当前仓库状态满足」，不可达就不写死；可比阈值须附当前实测值作参照。
2. **A 派发限行 / 少长文**（`TEAM` §三·十二 已固化）：A 消息与合同只给目标 / 判据 / 路径，不贴长输出；证据只给路径，细节由 B 回贴。
3. **成本快照改 B 执行**（C8 已落规则）：`cost-before` 由 **B 在 claim 首步**跑并回四字段；`cost-after` / `contract_close` 同由 B 跑，A 只收路径与输出——从流程上消除 A 代跑工具。
4. **blocked 前先自检口径**：B 遇「判据不可达」同样 1 轮内报 blocked，但 blocked 时同步给「可达替代口径」与实测值，减少 A 裁定往返。
5. **不调阈值**：双判据（≤基线×0.85 且 ≤30M）不变；「记超 + 复盘」为常态处理，不为单批记超回退口径。
