## INC-007 `git add -A` 把执行主管未完成的脚本卷进 docs 提交（2026-11-12，复发：INC-004 同类）
- 现象：2026-11-12 19:13，主持整合「汇报预算 + 审查触发收紧」文档时提交 `09507a4`，
  这个 `docs:` 提交里包含执行主管当时**尚未完成**的 `tools/check_ui_state.py`（211 行）；
  提交信息只讲文档，与内容不符。随后执行主管在 `94e7bdf` 补齐该脚本的最终版本。
- 根因：共享工作区里两个成员同时动手；主持提交前没有 `git status` 逐文件确认，
  直接 `git add -A`——与 INC-004 同一根因，说明「禁止 git add -A」这条固化只写在文档里、没变成动作。
- 影响：提交可追溯性受损、docs 提交带上未测试的工具；脚本内容未丢失（最终版以 `94e7bdf` 为准），
  但「一个提交一件事」再次被破坏。
- 处置：不改写已推历史（append-only），记录在案；整改项并入 `tools/precommit_check.sh --scope`。
- 固化：**主持提交前必须 `git status` 逐文件确认**；**执行主管有未提交改动时先自提交再交付**
  （不留未提交文件给主持看到）；提交前跑 `tools/precommit_check.sh --scope <路径>`，
  越界文件会被拦下（该脚本 2026-11-12 已入库）。

## INC-006 `statusText` 只写不读，所有提示对用户不可见（2026-11-12 发现）
- 现象：存档/读档/OTA 失败等提示写入 `activity.statusText`，但整个 App 没有任何地方读它渲染，
  用户看到的是「点了没反应」。
- 根因：状态变量在早期版本引入后，渲染它的那一行在后续 UI 改版里被删掉，没人发现——
  因为**没有任何测试或检查覆盖 UI 状态绑定**。
- 影响：所有操作反馈静默；「不许静默失败」这条规矩在实现层形同虚设。
- 处置：内容区底部加临时状态行（2.5–3s 自动清除）。
- 固化：新增 UI 状态变量时，必须同时有读取点；`verifier` 检查清单加一条
  「grep 每个 `mutableStateOf`/`statusText` 是否有对应渲染」。已记入 TODO。

## INC-005 队友 amend 已推提交，导致本地/远端分叉（2026-11-12）
- 现象：`artisan` 在 `80f4306`（已推送）上 `git commit --amend`，同时 Lead 刚在其上提交了
  `a56d604`；amend 把 docs 提交一并卷入，随后 `reset --soft` 重做，本地变成
  `7a722ad + cad39b0`，与远端 `80f4306 + a56d604` 分叉。
- 根因：共享工作区里两个 agent 同时操作 HEAD；amend 会改写已有提交。
- 影响：分叉；需二次强推对齐（内容未变，仅 hash 变化）。
- 处置：Lead 强推 `cad39b0` 统一。
- 固化：**已推送的提交禁止 amend / rebase / reset**，只能追加新提交（append-only）；
  需要撤销就走 `git revert`。Lead 提交前先 `git status` 确认队友没有未提交改动。

## INC-004 Lead 的 `git add -A` 卷走了队友的未提交改动（2026-11-12）
- 现象：`66940b2`「feat: 会话健康检查脚本…」实际含 docs + `session_health.mjs` +
  两支 Kotlin 改动（队伍详情、OTA 日志/回调），提交信息与内容不符。
- 根因：队友 `artisan` 同时在工作区改文件（尚未 commit），Lead 执行了 `git add -A` 一并打包；
  CI 自动发版时把这条 message 当成了 OTA 更新说明。
- 影响：追溯性受损、OTA 说明词不达意；内容本身正确、无丢失。
- 处置：不重写已推历史（避免二次强推）；记录在案，后续由新提交覆盖说明。
- 固化：**Lead 提交前必须 `git status` 逐文件确认，禁止 `git add -A`**；队友有 shell 后，
  改动应由队友自己 commit，Lead 只做 review + push。

## INC-003 交接文档写了不存在的文件（2026-11-12）
- 现象：`tools/gen_files_index.py` 的 OVERRIDES 里有一条 `incident_notes.md`，仓库中并无此文件。
- 根因：写生成器时凭印象补条目，没有用 `ls` 核对。
- 影响：索引文档失真，新人按图索骥会找不到文件。
- 处置：改为真实存在的 `docs/INCIDENTS.md`（本文件）。
- 固化：`gen_files_index.py --check` 只检查“已跟踪文件是否有描述”，不检查“描述是否指向存在文件”→ 加入交接清单：**任何文档引用的路径都要 `ls` 验证**。

## INC-002 CI 连红 8 次（2026-11-12 03:51–05:26）
- 现象：CI 连续失败，期间用空提交和往源码塞 `// build trigger` 触发构建。
- 根因：① `MainActivity.kt` 缺 `detectTapGestures` 的 import；② `KeyPadArea` 残留重复布局块，多一个右花括号（`51cb162` 插入新布局没删旧块）。

- 处置：补 import、删 23 行重复代码、重发 `build-cc9d0ad`、删除错包。
- 固化：`NATIVE_EMU_TODO.md` 写入自检三条（grep import / 数花括号 / 说明预期 CI）；`auditor` 提示词把“空提交触发构建”列为卫生问题。

## INC-001 长会话空回复（2026-11-12 04:08）
- 现象：某会话第 299/301/302 轮只产出 reasoning、没有正文，界面表现为“不回复”。
- 根因：会话已达 302 轮、18320 条事件、压缩 2 次、日志 10 MB；模型偶发空响应。
- 影响：交接任务（写 HANDOFF）实际未完成，用户以为卡死。
- 处置：换新会话接手；原会话恢复后继续。
- 固化：交接阈值写进 `HANDOFF.md`——**超过 ~100 轮或压缩过 2 次就交接**；新会话先读 HANDOFF 而不是接着聊。
