## INC-004 Lead 的 `git add -A` 卷走了队友的未提交改动（2026-11-12）
- 现象：`66940b2`「feat: 会话健康检查脚本…」实际含 docs + `session_health.mjs` +
  两支 Kotlin 改动（队伍详情、OTA 日志/回调），提交信息与内容不符。
- 根因：队友 `artisan` 同时在工作区改文件（尚未 commit），Lead 执行了 `git add -A` 一并打包；
  CI 自动发版时把这条 message 当成了 OTA 更新说明。
- 影响：追溯性受损、OTA 说明词不达意；内容本身正确、无丢失。
- 处置：不重写已推历史（避免二次强推）；记录在案，后续由新提交覆盖说明。
- 固化：**Lead 提交前必须 `git status` 逐文件确认，禁止 `git add -A`**；队友有 shell 后，
  改动应由队友自己 commit，Lead 只做 review + push。

## INC-003 交接文档写了不存在的文件（2026-11-12）
- 现象：`tools/gen_files_index.py` 的 OVERRIDES 里有一条 `incident_notes.md`，仓库中并无此文件。
- 根因：写生成器时凭印象补条目，没有用 `ls` 核对。
- 影响：索引文档失真，新人按图索骥会找不到文件。
- 处置：改为真实存在的 `docs/INCIDENTS.md`（本文件）。
- 固化：`gen_files_index.py --check` 只检查“已跟踪文件是否有描述”，不检查“描述是否指向存在文件”→ 加入交接清单：**任何文档引用的路径都要 `ls` 验证**。

## INC-002 CI 连红 8 次（2026-11-12 03:51–05:26）
- 现象：CI 连续失败，期间用空提交和往源码塞 `// build trigger` 触发构建。
- 根因：① `MainActivity.kt` 缺 `detectTapGestures` 的 import；② `KeyPadArea` 残留重复布局块，多一个右花括号（`51cb162` 插入新布局没删旧块）。
- 影响：两小时无可用构建；Release 一度发出旧包（`build-c7996e9`）。
- 处置：补 import、删 23 行重复代码、重发 `build-cc9d0ad`、删除错包。
- 固化：`NATIVE_EMU_TODO.md` 写入自检三条（grep import / 数花括号 / 说明预期 CI）；`auditor` 提示词把“空提交触发构建”列为卫生问题。

## INC-001 长会话空回复（2026-11-12 04:08）
- 现象：某会话第 299/301/302 轮只产出 reasoning、没有正文，界面表现为“不回复”。
- 根因：会话已达 302 轮、18320 条事件、压缩 2 次、日志 10 MB；模型偶发空响应。
- 影响：交接任务（写 HANDOFF）实际未完成，用户以为卡死。
- 处置：换新会话接手；原会话恢复后继续。
- 固化：交接阈值写进 `HANDOFF.md`——**超过 ~100 轮或压缩过 2 次就交接**；新会话先读 HANDOFF 而不是接着聊。
